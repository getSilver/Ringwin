# 02 用核心资产投影识别两腿敞口

## Question

两腿的敞口、报价和合约倍率如何获得可追溯的共同身份？

## What to build

正常节点从核心投影读取资产关联，页面显示配对依据或缺项。

## 验收条件

- [x] 异名同敞口正确关联；同名异资产保持独立；缩放合约按登记单位及倍率比较。
- [x] 缺少敞口或报价登记时指出来源及缺项。
- [x] 关联变更撤销旧候选，重启按当前版本重建，证据保留原关联版本。

## 实现证据

- Windows，OKX 与 Hyperliquid 的合成公共协议响应，经原生适配器、HTTP 扫描和内存历史验证。9 项定向用例通过，含异名同敞口、同名独立、OKX 线性合约按 `ctVal=0.1` 换算、缺登记定位、投影失败撤销、登记改版与重启、旧版证据复算。
- 单独构建原生核心投影探针，重放未封存的核心夹具日志得到空登记，替换为损坏日志后拒绝读取。正常 Web 启动配置只把探针用于资产读取。前端扫描 API 检查和扫描页面定向 TypeScript 检查通过。
- 当前投影输入为可独立重放的 `shard-*.journal`。封存部署的正式登记和实际场所行情需另行验收。合约换算覆盖已支持的 OKX 线性 `ctVal`；未知缩放代码继续按来源隔离。
