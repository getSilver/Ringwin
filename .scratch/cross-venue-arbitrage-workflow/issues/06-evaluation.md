## Question

用户凭哪些材料区分观察价差和可执行机会？

## What to build

节点启动、重启或输入变更后，按当前盘口及已登记模型、校准、资金和风险材料评估完整周期。

## 验收条件

- [x] 同结算币路线可独立验收，页面显示两腿、方向、模式、固定金额净边际、计划收益、可执行量、费率版本及逐腿行情年龄。
- [x] 分别移除一项材料或使行情失效，页面显示具体原因，旧推荐撤回。
- [x] 从归档输入重算同一候选，核对数量、金额和版本。

## 实现与验收证据

- 机会页显示两腿、方向、模式、计划净收益、双腿可执行量、费率版本和评估截止时的逐腿盘口年龄。固定档使用参考名义金额和当前盘口下买腿金额均为 5,000 的材料。缺档或金额不匹配时显示原因。
- Windows 离线使用正式 OwnerSession HTTP、Zig 公共行情适配器及当前机会页。OKX 现货和 Hyperliquid 标准永续使用 production 路由的合成协议数据，HYPE／PURR 均使用 USDC 报价和结算。HYPE 双 IOC 显示 959.93 bp、1.6 HYPE、479.968 USDC、费率版本 1 和两腿 0.0 ms。移除校准后页面撤回推荐。前端提交为 RingwinUi `26ade2a`。
- 定向回归逐项移除模型、校准、资金、风险和费率，并使盘口失效，验证具体原因及推荐撤回。改变已校验的目标量后，原 $5K 值撤回。同一时钟域重启时重新采样并读取已登记材料和费率。Windows 系统时钟身份在两个独立进程中实测一致。
- 归档重算比对数量、完整周期金额、固定档结果和输入版本。新归档采用 `scanner_inputs_v3`，旧格式按当时的字段重算。派生历史保留在进程内存中。
- 48 项相关 Python 测试、前端扫描 API 和展示检查、TypeScript 类型检查及定向 Chromium 页面验收通过。无全量构建或测试。[页面验收截图](../../build/evaluation-06/evaluated.png)
