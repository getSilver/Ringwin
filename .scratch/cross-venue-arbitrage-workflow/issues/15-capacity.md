## Question

给定范围能持续覆盖多久，原始盘口是否还可重放？

## What to build

按来源和大小轮转捕获段，校验归档可重放后回收；页面显示容量故障和受影响来源。

## 验收条件

- [x] 从已回收热段的候选按双腿原始序号、版本和时刻重放。
- [x] 按 16、64、256 个选中品种记录全轮耗时、双腿时差 P95/P99、有效覆盖率、请求量、429 次数与每日存储增量。
- [x] 注入慢来源、重连、磁盘满和目录变更，验证范围、过期撤回与预热；报告实测瓶颈及可支持规模。

## 实现证据

- Windows 本机使用 OKX production 现货与 Hyperliquid production 标准永续的合成公共协议响应。正式 native RawIngress 后台校验并归档各来源的已关闭段。32 KiB 测试预算触发轮转时双腿仍可持续发布，已回收热段的候选可逐腿恢复原文并复算。
- 三档首轮耗时分别为 10.437、55.328、311.203 秒。16 盘口重复运行八轮，峰值新鲜覆盖 100%，均值 48.78%。三档完整口径、双腿时差、流量、存储增量及规模边界见[容量验收报告](../../../docs/research/2026-11-22-scanner-capacity.md)。
- 慢行情来源、延迟归档、断连重连、磁盘满、目录变更和 429 退避通过定向故障注入。RingwinUi 提交 `1e9c523` 在机会页显示剩余容量及受影响来源，API 契约、TypeScript 检查和生产构建通过。
