## Question

候选或 Web 会话消失后如何管理批准？

## What to build

从策略页按核心持久身份读取有效名单、请求回执并撤销，可用预先存在的核心批准验收。

## 验收条件

- [x] 停扫描、退市和 Web 重启后均能找到并撤销原批准。
- [x] 对丢失回执的请求按原身份查询或重试，回执及名单一致。
- [x] 有效状态和历史回执分别管理；历史容量满仍可撤销，新开仓立即受限。

## 实现与证据

RingwinUi 策略页（`547dcae`）和内置 Web 均从核心读取有效名单与已失效批准，并按 StrategyInstance、VirtualPortfolio 和批准身份请求回执或撤销。撤销身份沿用目标批准身份，通过独立操作查询。批准回执保持原版本和提交序号。

- Windows 离线联合回归使用合成 Demo × Testnet 双腿数据，贯通认证 HTTP、中继和 Zig Writer。停止扫描、清空候选、删除一腿映射并重启 Web 后，新会话仍找到并撤销原批准。另一条定向 Writer 测试使用规则版本更新模拟交易品种失效，确认该批准仍可查找和撤销。
- HTTP 回归注入提交后丢失撤销回复，新 Web 会话按原身份查询并重试，返回同一回执和空名单。Writer 定向回归覆盖错误组合拒绝、日志重放、快照恢复及原批准回执。
- 256 条批准历史满载时，Writer 通过预留回执位置撤销现行批准，当场拦截新开仓和风险增加改单。撤单和减仓回归通过。原批准历史仍保留 256 条上限，满载时继续拒绝新增批准。
- 验证覆盖变更涉及的 Zig 过滤用例、两项 Python HTTP 回归、RingwinUi 类型检查及控制 API 检查。数据来自离线夹具。
