## Question

用户选定的两腿能否直接进入匹配？

## What to build

依据用户范围和共同资产生成路线，逐腿记录方向、产品、请求环境与实际行情来源。

## 验收条件

- [x] Demo × Testnet 和反向选择均进入匹配；新增可选 Venue 无需修改组合规则。
- [x] 覆盖双现货、现货与永续的两种方向及双永续，后端无产品或环境组合白名单。
- [x] 盘口、库存或执行能力缺失时页面标明具体腿和原因。

## 实现证据

- 19 项定向 Python 用例通过。通过 Windows 上的原生行情适配器和认证 HTTP API 注入离线合成协议数据，验证 OKX Demo 请求使用 production 公共行情，Hyperliquid Testnet 请求使用 Testnet 行情。测试覆盖反向选择、全部产品组合、额外 Venue 身份、首次缺盘口与恢复，以及新旧归档回放。
- RingwinUi 扫描 API 检查和受影响文件的 TypeScript 类型检查通过。候选详情逐腿显示方向、品种、请求环境、公共行情来源及阻塞原因。公共扫描节点缺少私有账户库存和执行能力证明时显示未核实。当前评估器对现货卖出开仓和跨环境资产账务归属仍有约束。
- 当前快照上限为 256 行，每对市场生成六个方向与模式组合。覆盖容量由 [14](14-coverage.md) 接续验证。
