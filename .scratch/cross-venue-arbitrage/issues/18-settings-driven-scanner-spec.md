## Question

如何让用户在前端设置中保存交易所，在跨交易所套利的扫描范围中直接选择这些交易所，并通过公共接口动态获取品种和规则，移除固定交易所组合与三个 BTC 品种的限制，同时保留现有 Python 调度、Zig 行情处理和 Python 扫描计算链路？

## Problem Statement

当前扫描运行组装固定 OKX／Hyperliquid 的路由和协议选择，OKX 品种限制还深入到 Zig 解码器和行情适配器。扫描范围只能选择手工登记的市场，无法从设置中配置的交易所直接发现市场。前端交易所设置目前只存在于页面 React 状态，刷新和服务重启后不能恢复，也没有成为扫描器的数据来源。

页面混用了固定交易所名称和 Venue 数字占位，交易所筛选、范围、行情来源、机会方向及历史无法一致使用用户在设置中配置的名称。用户不希望额外维护可信品种文件、声明行情能力或执行二次启用操作。

## Solution

用户在现有设置页选择已接入的交易所类型，填写必填的交易所名称和环境后保存。现有 Python Web 控制面将设置持久化到服务端运行数据目录。扫描范围直接展示保存的交易所名称，用户选择交易所、产品、资产及深度条件后应用，扫描器据此增减行情订阅。

扫描器通过对应交易所公共接口获取市场目录与 InstrumentRules 所需的观察数据，无须用户填写品种清单。公共元数据经实际行情适配器校验、规范化后进入扫描目录。保留 Python 请求和调度 → Zig MarketFeedAdapter／规范行情投影 → Python 扫描计算的现有链路。

## User Stories

1. 作为 SystemOwner，我希望在设置中选择已接入的交易所类型，以便配置正确的行情接入实现。
2. 作为 SystemOwner，我希望保存必填的交易所名称，以便扫描页面使用我配置的名称。
3. 作为 SystemOwner，我希望保存交易所环境，以便明确扫描使用的行情来源。
4. 作为 SystemOwner，我希望刷新页面后恢复交易所设置，以便不必重复填写。
5. 作为 SystemOwner，我希望服务重启后恢复交易所设置和扫描范围，以便继续使用之前的配置。
6. 作为 SystemOwner，我希望保存失败时看到错误且旧配置保留，以便不会误认为设置已生效。
7. 作为 SystemOwner，我希望保存交易所后即可在扫描范围选择它，以便不再手工编辑市场配置文件。
8. 作为 SystemOwner，我希望不必声明行情能力或另外启用扫描接入，以便配置步骤简单明确。
9. 作为 SystemOwner，我希望扫描目录自动获取交易所公开的品种、产品与规则，以便扫描不局限于代码中的 BTC 白名单。
10. 作为 SystemOwner，我希望同时选择多个交易所和产品，以便自行决定跨所观察范围。
11. 作为 SystemOwner，我希望继续配置资产纳入、排除及深度条件，以便复用现有范围语义。
12. 作为 SystemOwner，我希望新发现品种遵循现有新品种纳入策略，以便目录刷新不会意外扩大扫描范围。
13. 作为 SystemOwner，我希望应用范围后只增减相关订阅，以便不打断其他正常来源。
14. 作为 SystemOwner，我希望修改交易所名称后所有扫描展示使用新名称，以便展示保持一致。
15. 作为 SystemOwner，我希望改名不改变交易所身份和扫描范围，以便无需重新配置订阅。
16. 作为 SystemOwner，我希望删除交易所时同步清除对应扫描范围和订阅，以便不会保留失去设置归属的来源。
17. 作为观察者，我希望筛选、名称搜索、行情来源、机会方向、历史和详情均使用配置名称，以便无需理解内部数字身份。
18. 作为观察者，我希望元数据加载中或请求失败时保留交易所选项并显示实际状态，以便区分配置存在与网络加载结果。
19. 作为观察者，我希望规则变更或行情失效时受影响机会立即撤销并重新预热，以便不使用旧规则或陈旧盘口。
20. 作为 SystemOwner，我希望公共扫描独立于交易账户、凭证和策略加载，以便单独管理观察范围。
21. 作为运维人员，我希望沿用现有 Zig 原始行情记录和规范投影，以便继续追查扫描输入。
22. 作为维护者，我希望新增交易所行情适配器后，设置和扫描页面通过同一目录接入，以便不用修改交易所名称判断或扫描组合白名单。

## Implementation Decisions

### 设置持久化与身份

- 复用现有 OwnerSession、CSRF 和 Web 控制面，提供交易所设置的读取、保存、修改和删除接口；前端状态只作编辑草稿，不作为持久化来源。
- 服务端运行数据目录使用 `exchange-settings.json` 保存交易所设置，包含 schema、配置版本、稳定设置身份、VenueIdentity、交易所类型、必填显示名称及环境。交易所类型决定实际适配器，显示名称不参与协议路由。
- 使用现有扫描配置持久化方式：同目录临时文件、完整写入、flush、fsync、原子替换；成功落盘后才报告保存成功。校验或写入失败保留旧配置，启动时读取完整已保存版本。
- 保存接口携带预期配置版本，拒绝并发旧版本覆盖。缺少文件表示初始空设置，不预置 OKX／Hyperliquid 扫描范围；损坏文件明确报错，不静默覆盖为空设置。
- 名称在创建和修改时校验非空。扫描视图向前端返回设置名称目录，前端直接按稳定身份解析；不增加“Venue 1”或“交易所配置缺失”等名称替代分支。
- 交易所名称与 ExchangeAccount 的账户名称分开。公共扫描按 Venue 和环境共享，多个账户不产生重复的公共来源；账户凭证及交易启用状态不控制公共扫描。相同 Venue／环境的设置避免重复登记，需要多个账户时复用交易所归属。
- 改名只更新展示，不重建订阅、不改变 InstrumentIdentity 或候选身份。历史在当前服务保留期内按稳定身份关联名称；删除设置后，历史仍使用保留的名称信息，不能退化为数字占位。
- 环境变化按来源切换处理，旧来源结果失效；删除设置同步移除对应范围、释放本扫描器订阅并撤销相关候选。保存与运行状态协调失败时明确返回失败或待处理状态，不报告删除完成却继续发布旧来源结果。其他消费者的订阅所有权保持独立。

### 扫描范围与动态发现

- 扫描范围的交易所选项直接来自已保存设置。设置页仅提供已经实现行情接入的交易所类型，保存后即可选择，不增加能力声明、资格登记或另行启用操作。
- 元数据加载状态与交易所是否可见分开。正在加载或暂时请求失败不会让设置中的交易所从选项消失；未完成加载的来源不能发布有效盘口或候选，界面展示实际加载／故障状态。
- 保留现有范围的产品、环境、资产纳入／排除、深度金额与新品种策略语义，以及草稿、预期版本、已保存配置和实际运行状态的区分。
- 扫描范围继续独立保存为 `scanner-config.json`。服务重启加载设置与范围，默认停止，不因恢复配置自动连接行情或启动扫描；用户启动或请求加载市场目录时再执行所需公共请求。
- 移除 `scanner-market.json` 的启动条件、读取依赖及手工品种登记流程。不迁入另一份静态品种白名单，也不要求用户编写 tick、lot、合约乘数或品种身份。
- 元数据来自交易所公共接口，首次发现及运行中定期刷新。Python 负责请求、分页与调度，交易所协议字段由各自适配器解释；发现结果提供产品、相关资产、交易状态、价格／数量约束、结算与合约规格。
- 公共接口可能有分页和大响应，元数据发现必须完整处理声明范围内的结果；保留有界请求、消息和驻留容量，达到上限时明确报错或显示覆盖范围，不能截断后声称已完整发现。扫描只订阅所选范围，不因发现全部品种而自动订阅全市场。
- 新发现的 Instrument 是否纳入运行范围遵循现有新品种策略；规则变化、退市、暂停和消失影响对应来源及候选，恢复后重新预热。
- InstrumentIdentity 和资产关联在重复发现及重启间保持稳定。不同 Venue／产品／合约规格不能共用 InstrumentIdentity，不能仅凭同名字符串认定跨所资产等价。
- 元数据在扫描观察范围内形成经验证、带版本和来源证据的规则。复用现有 AssetDefinition 及资产身份规则，不从 lot 或提现精度推测核心资产原子单位，不让自动观察直接修改核心 AssetDefinition、InstrumentRules 或交易授权；无法确定单位的品种明确报告原因且不参与有效机会计算。

### 保留 Python／Zig 链路

- 保留 Python 公共 transport、订阅管理、刷新调度与扫描计算；保留 Zig native worker、MarketFeedAdapter、规范行情投影、RawIngress 捕获和现有审计接口。
- Python 运行组装按设置中的交易所类型选择对应实现，不保留固定“两家组合”或“非 OKX 一律按 Hyperliquid”的推断。端点、元数据请求、盘口请求与环境映射归属交易所实现，扫描范围无需维护公共 URL。
- Zig 入口保留明确的已实现适配器选择。删除业务流程只接受两个 Venue 数字身份的限制，新增类型在一个清晰的组装入口登记；无需动态插件或通用协议框架。
- OKX 的协议解码器、行情适配器、Python 配置组装和 native worker 配置合同一起改造，将三个 BTC 枚举及固定状态数组改为有容量约束的品种绑定。只删除 Python 白名单不算完成。
- Python／Zig 交换动态品种身份、规则版本和适配器必要绑定数据；对 schema、session、连续序号、环境、单位和容量继续验证。规则和绑定须与实际元数据一致，不能由页面绕过验证直接注入有效行情。
- 保留请求环境与实际行情环境的区分，现有环境映射在对应交易所实现内明确执行和展示，不把生产公共行情标成 Demo 行情。
- 全部扫描展示统一使用设置名称，包括交易所多选和筛选、按名称搜索、范围草稿／生效范围、行情与故障来源、机会方向、历史、详情和操作提示。内部数字身份可留作证据字段，不作为交易所名称替代。
- 扫描独立只读，不授予 PairTradingAuthorization 或 InstrumentTradingAuthorization；缺少研究、模型、费用或校准材料时继续按现有语义展示缺项。

## Testing Decisions

- 用户已确认复用最高层验收接口：前端设置／扫描范围 → 现有 Web 控制面 → Python 调度 → 实际 Zig MarketFeedAdapter／投影 → Python 扫描结果。只在公共网络 transport 处提供确定性交易所协议输入，不替换适配器、规范盘口或扫描结果。
- 复用现有扫描内部整合的认证、CSRF、断连、规则不匹配、TTL、局部范围变更、环境切换、迟到结果、RawIngress 和正常启动回归；浏览器复用已有扫描集成验收入口。
- 验证新增设置后扫描范围直接出现配置名称；刷新页面和重启服务恢复设置及范围，重启默认停止；完全没有旧市场配置文件也能运行完整链路。
- 验证空名称在保存处被拒绝、并发版本冲突、写入失败与不完整临时文件不会损坏已保存配置；复用既有配置存储公开接口测试，不断言内部调用顺序。
- 验证改名后所有当前和历史展示、名称搜索及筛选一致变化，内部身份和未受影响订阅保持稳定；删除与环境切换正确撤销相关范围和候选，迟到结果不能复活来源。
- 通过公共接口元数据夹具提供至少一个原三个 BTC 品种之外的 OKX 品种和 Hyperliquid 品种，实际经过 Zig 解码与规则转换，验证资产、合约乘数、价格和数量单位及最终扫描覆盖；不能只验证 Python 目录接受。
- 验证新增元数据、规则变化、暂停／退市、请求失败恢复、分页与容量，以及新品种纳入开关。超过容量明确报告，不能产生声称完整的部分目录。
- 复用 MarketFeedAdapter 契约补充动态品种隔离与错误单位拒绝测试；针对实际新增分支和失败路径测试，不为私有辅助函数或固定实现结构新增镜像测试。
- 验证所有交易所名称展示来自设置，无固定 OKX／Hyperliquid 展示分支、Venue 数字占位或名称缺失替代路径；扫描无凭证读取、交易账户启用或策略加载前置要求。
- 确定性协议输入的内部验收与在线端点、真实行情新鲜度及长期运行验收分别记录。内部通过不授予交易或生产资格。

## Acceptance Criteria

- [ ] 设置页通过现有认证控制面读写交易所设置，名称必填；服务端原子持久化、版本冲突和失败保留行为通过。
- [ ] 页面刷新与服务重启恢复设置和扫描范围，重启默认停止。
- [ ] 保存交易所即可在扫描范围按配置名称选择，无能力声明或二次启用步骤。
- [ ] 移除旧市场配置文件后正常入口仍可发现市场、配置范围并启动扫描。
- [ ] 品种与规则来自公共元数据，至少一个原白名单外 OKX 品种经过实际 Python／Zig 链路验证。
- [ ] 应用范围、动态目录更新、新品种策略、环境切换、改名和删除行为符合上述合同，未受影响订阅保持独立。
- [ ] 现有 Python 请求和调度、Zig 行情适配器和证据链、Python 扫描计算保持完整，动态绑定的 schema、单位与身份校验通过。
- [ ] 所有扫描交易所展示与名称搜索使用设置名称，历史也无数字名称占位。
- [ ] 单位不明确、规则变化、退市、网络故障和超容量不产生有效旧候选，恢复后重新预热。
- [ ] 经用户确认的完整链路、持久化回归与适配器契约验收通过，内部报告明确区分合成协议输入和在线行情证据。

## Out of Scope

- 将扫描器改成全 Python、删除 Zig native worker 或重新实现一套行情接缝。
- 能力声明页面、能力资格登记、通用插件框架、额外控制面或新的数据库。
- 实现第三家交易所的协议；本规格移除固定组合与展示耦合，为已实现行情适配器提供一致接入方式，前端填写名称不能生成新协议实现。
- 手工维护新的可信品种白名单，或通过 UI 编辑原始盘口、tick、lot、合约乘数与核心资产定义。
- 凭证录入、真实或 Demo 下单、核心交易授权变更、12–15 经济／运行资格关闭。
- 在线行情及持续运行资格验收、部署、GitHub Issues 同步。
- 本次文档发布即开始实现或将验收条件标为已完成。
