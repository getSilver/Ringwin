## Problem Statement

Python 扫描器已有规范输入到完整替换快照及展示 JSON；当前页面为样例数据，缺少运行管理、人工观察范围、证据查询、历史统计及核心确认接线。07 的 resolved 只覆盖策略离线范围，不证明 Web、Host、Venue 已连接。

用户要求功能完整且实现精简，已退出 Ponytail。交易所由人工在需要时加入，不规定首批名单；适配器真实行情能力核对放到最终接入阶段，不阻塞本次功能设计和页面 Demo。

## Solution

在现有 Web 控制面和 RingwinUi 中提供扫描运行、范围配置、当前候选、证据详情、历史统计及操作记录。扫描独立只读运行，与交易共用经济／预测评估。UI 只提出白名单选择，控制面授权并转交，核心验证、应用并确认生效。

## User Stories

1. 作为 SystemOwner，我希望启动扫描，以便持续观察配置范围内的机会。
2. 作为 SystemOwner，我希望看到启动、预热、运行、降级、停止及故障阶段，以便理解实际状态。
3. 作为 SystemOwner，我希望停止后撤销当前推荐，以便旧结果不会保持有效。
4. 作为 SystemOwner，我希望停止扫描不影响既有持仓退出和对账，以便分别管理观察与交易。
5. 作为 SystemOwner，我希望人工增删 Venue，以便自行决定接入范围。
6. 作为 SystemOwner，我希望逐 Venue 选择环境、产品、资产与品种，以便精确配置观察范围。
7. 作为 SystemOwner，我希望显式控制新上市品种是否纳入，以便范围不会意外扩大。
8. 作为 SystemOwner，我希望区分草稿、提交和生效版本，以便识别尚未生效的修改。
9. 作为 SystemOwner，我希望局部范围变更不打断其他扫描，以便隔离变更影响。
10. 作为观察者，我希望看到连接、规则加载、预热、新鲜度和连续性，以便解释候选缺失。
11. 作为观察者，我希望故障只使受影响候选失效，恢复后重新预热，以便避免陈旧数据。
12. 作为观察者，我希望按资产、Venue、方向、模式、状态筛选和排序，以便定位机会。
13. 作为观察者，我希望区分双 IOC 与两种 Maker 腿，以便不混用模式证据。
14. 作为观察者，我希望查看数量、计划收益、目标、概率下界和最差路径，以便理解机会。
15. 作为观察者，我希望查看模型、校准、规则版本和数据截止点，以便追查依据。
16. 作为观察者，我希望缺研究证据时仍展示待验证配对，以便了解观察覆盖。
17. 作为观察者，我希望无新行情时结果也过期，以便旧推荐不会滞留。
18. 作为观察者，我希望重连后旧会话结果不覆盖新结果，以便状态保持一致。
19. 作为 SystemOwner，我希望从候选提交配对、方向和模式请求，以便复用观察上下文。
20. 作为 SystemOwner，我希望请求绑定核心认可的账户、品种和策略归属，以便符合核心要求。
21. 作为 SystemOwner，我希望区分待核心确认、接受、拒绝和结果待查，以便不把提交视为生效。
22. 作为 SystemOwner，我希望超时按原身份查询，以便避免重复授权。
23. 作为 SystemOwner，我希望撤销同样经核心确认，以便保留订单、资金和退出责任。
24. 作为观察者，我希望查询历史评估和独立事件，以便追踪机会变化。
25. 作为观察者，我希望历史分布有明确门槛、数量、模式和时区，以便统计可解释。
26. 作为观察者，我希望自然结束与观察中断分开，以便持续时间不被误算。
27. 作为运维人员，我希望看到历史提交进度和缺口，以便识别记录不完整。
28. 作为研究人员，我希望历史关联行情、模型、参数及场景内容，以便保留期内复算。
29. 作为运维人员，我希望明细、事件、汇总分层保留且引用证据锁定，以便控制容量。
30. 作为 SystemOwner，我希望查看启停、范围修改及核心请求记录，以便追踪操作。
31. 作为评审者，我希望在独立 Demo 操作正常与异常流程，以便评估方案而不触发真实动作。

## Implementation Decisions

### 模块与合同

- 扫描模块保留 scan／display_json 并复用评估；运行管理负责输入和生命周期，历史模块负责保存与查询，现有 Web 负责授权及转交，UI 负责操作展示。复用已有模块，不另建控制面或权威账本。
- 公共行情沿 MarketFeedAdapter，执行沿 VenueAdapter；公共行情生命周期不绑死到账户连接。扫描输入仍须提供其合同要求的账户观察身份，观察身份不授予交易权限。
- 候选是派生数据，不伪装为权威 CanonicalEvent，不塞进 StrategyOutputFrame。Host 外候选传输须验证 schema、容量、会话、版本、序号和内容；display_json 不能代替网络输入验证。
- 扫描阶段独立于表示交易生命周期的 OperationalMode；现有接口是否覆盖所需控制行为须实施时映射，不能假定其已实现。

### 生命周期与人工范围

- 分离期望与实际状态，覆盖 Stopped、Starting、Warming、Running、Degraded、Stopping、Faulted；每次运行使用新会话。启动校验输入并预热，停止先撤销推荐，再停止本扫描的计算和输入。
- 共享行情连接按订阅所有权释放，不中断其他消费者。单数据源异常局部降级；自动重连不得撤销人工停止。
- 服务重启默认停止，自动恢复仅显式启用后执行，仍须重新预热。该默认策略是本规格拟定设计，不记录为用户单独批准的部署参数。
- 观察范围包含 Venue、Environment、产品、资产／Instrument 筛选、排除和新增品种策略。人工选择不自动扩展为交易白名单；不预设首批 Venue。
- 2026-11-06追加：Venue 和产品均为多选，一次将所选 Venue × 产品组合加入草稿，可按具体能力进一步校验；只跨不同 Venue 配对，不强迫所有组合都有资格。至少两所才能启动跨所扫描。
- 纳入资产与排除资产均可为空：纳入为空表示当前选定范围内全部已登记品种，排除为空表示无显式排除；显式排除优先于纳入。全量不等于自动接纳未登记或新上市品种，不依赖交易白名单。
- 用户确认流动性采用盘口可用深度，最低／最高金额均可为空，边界包含，0是有效值，非法数值、负值或倒置区间拒绝。每腿对已提供盘口买卖两侧分别累加规范价格×数量名义金额，再取较小值；两腿各自均需满足范围。该口径仅覆盖已提供的有界盘口（最多8档），不是全市场深度、24h成交额或实际可执行资金；单位必须绑定报价资产，UI通过可信精度映射转换USDT至atoms。
- 后续实现应让Python扫描公开接口接收版本化范围条件；Venue、产品和资产使用规范身份，过滤不产生授权。仍校验原观察集合与Plan绑定，范围内才评估；过滤掉的配对不能把合法原Plan误判为非法输入。启用深度条件时未知数量不能视作达标，陈旧／缺口／过期候选继续按既有健康语义撤销资格；过滤条件随配置版本及历史保存。本次仅更新规格，尚未实施此接口。
- UI须区分“全部已登记资产”“不排除”“深度不限”和具体数值，范围草稿与生效投影均展示这些条件。相同Venue／产品／环境组合重复提交只更新其条件，不能重复订阅；无匹配时显示筛选无结果，不能冒充运行故障。多产品候选详情必须标明两腿产品，避免同资产同Venue不同产品混淆。
- 草稿提交携带预期版本，服务端确认生效版本。移除立即撤销相关候选，新增预热后生效；其他范围继续运行。配置冲突拒绝，不能覆盖未知更新。
- 配对遵循资产、报价、产品、规则和方向约束；现货／现货仅观察。容量限制显式失败，不静默截断；扩容需实测验证。

### 结果与展示

- 保留 arbitrage_candidates_v1 完整替换语义；包络绑定运行会话、配置版本和快照序号。重复幂等、乱序拒绝、缺口重取完整快照；不能把源 cursor 当作跨会话全局身份。
- 稳定身份包含配对、方向、模式和 Maker 腿；数量选择和模式推荐继续由共享评估负责。每次读取更新 TTL，失联、计算失败、过期和缺口撤销受影响推荐。
- ID、金额、纳秒时间用字符串，数量和比率用精确分数；绑定资产单位及精度。浏览器不得直接用墙上时钟比较服务端单调时间，由服务端提供新鲜度和展示时间映射。
- evaluated／recommended 只表示评估，不授予统计或运行资格；trading_qualified 恒为 false。缺证据仍显示 pending 和原因，现货／现货仅观察。
- 完整周期计划收益与即时价差分别标注；收益率注明分母、数量和成本口径。缺少数据的 $5K 边际或可执行容量显示不可用，不虚构数值。

### 白名单与核心权威

- UI 提交选择与证据，Web 完成 OwnerSession 授权、格式校验、认证和转交，不修改 AuthoritativeTradingState。
- 请求绑定可信映射得到的 Venue、Environment、ExchangeAccount、Instrument、StrategyInstance／VirtualPortfolio、配对、方向、模式、预期配置版本及稳定幂等身份。candidate_id 和显示字符串不能作为授权依据。
- 核心通过既有 ConfigEvent／ControlCommand 合同验证账户归属、品种规则、模式能力、配置版本、策略激活和安全限制，持久应用后返回确认。当前核心是否能完整表达配对／方向／模式批准待源码映射；缺合同先补核心及公共测试，禁止控制面维护可绕过核心的生效白名单。
- 请求状态为 pending、accepted、rejected、unknown；accepted 绑定核心确认版本和权威进度。超时按原身份查询，不新建授权。撤销同样经核心，保留既有订单、预留、退出和对账责任。
- 配置获准不等于 EnableTrading 或发送许可。交易策略重新检查最新信号／行情／模型，继续经过资金、风险、预留、安全栅栏和 Gateway 复核，不补发旧机会。

### 历史持久化与统计

- 拟采用服务端本地 SQLite，保存运行／配置、评估批次／候选、独立事件、汇总和覆盖缺口，Web 提供授权分页查询。只保存扫描派生历史；RawIngress 和权威事实仍走 DurableStore。
- 单后台写入者、有界队列及明确批量提交屏障；一轮批次与候选原子提交。唯一键为会话和序号，重复幂等，同身份异内容拒绝。不按浏览器刷新频率写入。
- 保存 schema、输入游标、配置／规则／模型／校准版本、摘要、数据截止点、有效期、单位及评估结果。内容去重仍保留每轮时间与输入证据。
- 同配对／方向／模式／Maker 腿连续满足版本化统计门槛构成事件；自然失效、过期、断线、停机、配置变化和崩溃分开归因。未知区间不拼接，跨模式数量不直接相加成独立市场事件。
- 明确时区和时钟域；未闭合事件标为右删失或观察中断。收益分布注明按事件、时长或评估加权及代表值规则，热力图每个事件只归入一个互斥格子。
- 汇总可由明细／事件重建，绑定口径版本、来源区间及覆盖率；重算幂等，晚到记录明确修订范围。
- 展示最新与已提交序号、积压及存储健康。写入失败、队列溢出或崩溃尾部建立覆盖缺口，不声明完整历史；恢复把未闭合事件标为中断，不延长到重启时间。
- 引用现有行情归档及不可变模型、参数和冻结场景内容；摘要不等于可重放材料。材料清理后显示“结果可查、不可完整重放”。
- 分层保留明细、事件、汇总和证据；完成汇总与引用检查后清理，研究／验收引用锁定。保留天数、提交间隔、容量及备份恢复指标待测量；备份须数据库一致性备份，不能运行中只复制主文件。

### 独立页面 Demo

- 复用现有机会扫描的导航、主题、表格和热力图，使用独立 URL，原页面可继续访问。所有动作仅改变内存样例，刷新重置；不读凭证、不调用真实控制／交易接口、不实现 SQLite。
- 演示启停预热、人工范围与配置生效、故障／恢复／到期、候选筛选和详情、历史事件／缺口、白名单提交及模拟核心接受／拒绝／超时查询。
- Venue 示例不代表首批安排或真实能力；模拟核心接受不授予实际交易资格。正式集成不可复用前端模拟回执作为授权来源。

## Testing Decisions

- 主接缝：UI 操作 → 现有 Web → 运行管理／核心确认 → UI 与历史查询。只验证公开行为；2026-11-06 用户已明确确认此验收范围，Demo 仅模拟流程，不调用真实交易或授权接口。
- 扫描与准入复用已有公开测试、影子回放先例，覆盖口径一致、TTL、完整替换、容量、缺证据、身份和无交易副作用。
- 覆盖多所×多产品发现、同所不配对、双空资产、只排除及排除优先、流动性精确边界／零值／单边条件、上下限冲突、未知深度和报价单位不匹配；无scope时兼容原公开结果。
- 运行管理覆盖重复启停、停止后不重连、局部变更、共享订阅、版本冲突、旧会话及重新预热。
- Web／核心公共接缝覆盖未授权、伪造身份、错误归属、旧规则／配置、幂等冲突；失败不得改变权威状态。接受配置后仍须最新评估及独立发送许可。
- 临时 SQLite 验证原子性、幂等、写入失败、恢复、缺口、删失和统计去重、汇总重算、清理锁定与备份恢复。
- 浏览器验证独立入口、范围草稿与生效、启停、筛选详情、到期／恢复、历史过滤及所有白名单回执；覆盖窄屏和控件可访问名称。
- 最后核对适配器真实行情能力和运行接线，再验真实输入到 UI；离线与模拟结果不证明真实能力、经济或运行资格。
