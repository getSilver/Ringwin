## Question

把已选定的 OKX 与 Hyperliquid 接入现有扫描控制台，完成项目内部的运行组装、规范行情输入、扫描计算和 Web 操作展示。以正式内部链路和确定性协议夹具验收；交易所在线行情数据验收独立规划。

## Problem Statement

用户已有跨所扫描页面与扫描算法，但默认控制面未组装扫描接口，独立扫描工作区的实现尚未完整纳入正常运行入口。打开页面或加载策略不能直接获得一条可配置、可启停、可观察的跨所扫描链路。

当前源码还存在环境合同不一致：公共行情接缝没有 production 环境，而扫描配置已有该环境；各 Venue 的订单簿覆盖、规则映射和运行接线必须按当前实现核对。仅给页面返回扫描样例，或将模拟输入改名为真实行情，均不满足内部整合。

本规格的选定 Venue 为 OKX 与 Hyperliquid。用户明确要求以项目内部整合接通为主，实际端点、在线数据质量及持续运行验收放入另一计划，不作为本规格关闭的前置条件。

## Solution

在现有 Web 控制面和 RingwinUi 中，用户可以配置 OKX／Hyperliquid 的受支持环境、产品、资产与深度范围，启动扫描并查看预热、运行、降级、候选、证据及历史。正常入口组装正式行情 transport、MarketFeedAdapter、规范行情投影和扫描器；内部验收只在 transport 边界替换外部网络，用协议夹具经过实际适配器驱动同一链路。

没有模型、校准或成本证据时，仍可观察具备真实内部输入依据的价格、价差、深度与配对覆盖；机会评估明确显示缺项。启动扫描独立于 StrategyInstance 加载，不取得交易授权。

## User Stories

1. 作为 SystemOwner，我希望从现有登录入口访问扫描页，以便复用统一身份和会话。
2. 作为 SystemOwner，我希望直接配置并启动扫描，以便无需先加载交易策略。
3. 作为 SystemOwner，我希望选择 OKX 和 Hyperliquid，以便观察这两家 Venue 的跨所配对。
4. 作为 SystemOwner，我希望按 Venue 选择受支持环境，以便连接预期来源。
5. 作为 SystemOwner，我希望看到不支持环境的明确原因，以便不会误以为切换已经生效。
6. 作为观察者，我希望区分请求环境与实际行情来源，以便正确理解 Demo／Testnet 数据。
7. 作为 SystemOwner，我希望选择受支持产品及共同资产，以便限制观察范围。
8. 作为 SystemOwner，我希望纳入和排除资产均可为空，以便按现有范围合同配置扫描。
9. 作为 SystemOwner，我希望设置有单位的两腿深度上下限，以便筛选有足够盘口依据的配对。
10. 作为观察者，我希望查看实际目录和品种规则状态，以便识别未登记或规则缺失的品种。
11. 作为观察者，我希望同名但不同身份或结算资产的品种不会被错误配对，以便价差可解释。
12. 作为 SystemOwner，我希望区分配置草稿和生效版本，以便确认当前扫描范围。
13. 作为 SystemOwner，我希望启动后看到连接和预热状态，以便知道何时已有可用输入。
14. 作为观察者，我希望看到两家 Venue 的规范价格和深度，以便检查扫描依据。
15. 作为观察者，我希望最优价和多档深度的覆盖范围明确，以便不高估流动性。
16. 作为观察者，我希望缺少预测、校准或成本输入时仍能观察市场，以便扫描不因未获交易资格而不可用。
17. 作为观察者，我希望缺证据的评估显示原因，以便不会把观察价差当作可交易收益。
18. 作为观察者，我希望没有满足条件的机会时显示空结果，以便不会看到伪造候选。
19. 作为观察者，我希望查看候选的配置、规则、模型和输入证据，以便追查结果来源。
20. 作为观察者，我希望无新行情时结果自动过期，以便旧推荐不会长期滞留。
21. 作为观察者，我希望数据缺口或断连撤销受影响候选，以便不会使用不连续盘口。
22. 作为观察者，我希望恢复后重新预热，以便旧会话结果不能覆盖新状态。
23. 作为 SystemOwner，我希望修改局部范围只影响对应订阅，以便其他范围持续观察。
24. 作为 SystemOwner，我希望暂停和停止释放自身订阅，以便不影响其他公共行情消费者。
25. 作为 SystemOwner，我希望切换环境时清除旧结果并建立新会话，以便不同来源不混用。
26. 作为观察者，我希望刷新页面仍能查询服务端保留的历史，以便操作记录不只存在于浏览器。
27. 作为运维人员，我希望重启后恢复配置但保持停止，以便运行行为可控。
28. 作为观察者，我希望历史中断和覆盖缺口如实显示，以便不把未知区间计入完整事件寿命。
29. 作为运维人员，我希望容量不足和输入错误显式暴露，以便扫描不会静默截断数据。
30. 作为维护者，我希望通过单一完整链路验收上述行为，以便测试能够发现真实组装缺失。
31. 作为维护者，我希望正常启动无需手工导入测试模块，以便交付可独立运行。
32. 作为评审者，我希望内部整合报告与在线行情报告分开，以便准确判断已验证范围。

## Implementation Decisions

### 整合与职责

- 复用现有扫描控制台、扫描算法、历史模块、Web 控制面及 RingwinUi，核对独立工作区实现后做有范围的整合。保留当前工作树中无关修改，不整棵覆盖另一工作区。
- 公共行情 transport 和连接生命周期由运行组装拥有；Venue 协议及解码留在各自适配器；MarketFeedAdapter 输出 CanonicalEvent，规范行情投影提供扫描输入。交易核心保持单写者和无 I/O。
- 候选及扫描历史是派生数据，不成为 AuthoritativeTradingState 或伪造的 CanonicalEvent。扫描不借助 VenueAdapter 的执行能力连接公共行情。
- 扫描生命周期由现有控制面管理，不通过新增控制面 CLI 或 StrategyInstance 加载来绕行。
- 本规格是在原扫描页面规格之上的实施范围，不关闭原规格中的核心白名单、长期存储或在线数据条件。

### 环境、目录与身份

- 本轮选定 OKX／Hyperliquid；产品和品种由能力清单与配置共同限定，不默认订阅全市场。逐家核对现有实现后声明支持项，不预先承诺所有环境和产品组合。
- 统一扫描配置、MarketFeedAdapter、transport、RawIngress 和展示中的环境身份，补齐 production 公共行情语义；不得为通过当前校验而把主网标记为 demo。
- 区分真实公共行情、Venue 的 Demo／Testnet 与工程合成输入。Hyperliquid 的非主网来源按其实际 Testnet 能力表达，不制造统一 Demo 别名。
- 明确请求环境、实际来源环境与受支持端点配置；不支持组合拒绝并说明原因，不静默回退或合并环境。真实端点在线可用性留待独立行情验收。
- 注册 Venue、InstrumentIdentity、AssetDefinition、InstrumentRules 及版本证据；按规范资产身份和规则进行匹配，不只比较 Venue 品种字符串。
- 公共行情订阅不要求交易凭证。扫描输入若沿用账户观察身份，须通过可信配置明确绑定；观察身份不得被解释为 ExchangeAccount 交易授权。
- 环境改变建立新来源会话、撤销旧候选并重新预热；晚到数据按会话、配置和来源验证后处理。

### 正式数据链与机会评估

- 正常入口实际组装各 Venue 所需的 metadata、订阅、订单簿输入、定时过期和连接事件；使用现有 transport 能力，缺项在所属适配器或运行职责内补齐。
- 原始输入经过实际 Venue 解码、规范事件及行情投影后再进入扫描，不允许测试直接注入最终候选冒充整合。原始输入证据与会话、序号、规则及派生结果关联。
- 确认两家订单簿覆盖范围、数量单位和现有深度 codec 能力。覆盖不足时补齐必要实现或明确标记不可评估；最优买卖价不能伪装为完整多档深度，不估造可执行容量或滑点。
- 复用现有经济与预测评估接口，明确研究计划、模型、校准、费用及时间证据的供应和缺失处理。合成校准或测试计划仅在测试中使用，正常运行不自动获得伪造预测。
- 具备规范行情时独立展示观察价格、价差、深度与配对覆盖；评估材料不足时返回 pending 和具体原因。即时价差与完整周期净收益分别标注，未知值不能填零或生成推荐。
- 沿用完整替换快照和候选身份规则；大整数、金额和时间保留精度，跨进程输入继续校验版本、容量、会话、序列、cursor 和 payload。涉及 StrategyHost 时复用现有有界 framing，不增加共享内存能力。
- trading_qualified 恒为 false；观察、推荐或配置生效都不创建 OrderIntent、订单或风险预留。

### 操作、故障和历史

- 现有扫描 API 复用登录 Cookie、内存 CSRF、认证和授权；未组装能力返回明确不可用，不能用样例替代正常结果。
- 保留 Starting、Warming、Running、Degraded、Stopping、Stopped、Paused、Faulted 等既有运行语义，公开期望与实际状态。重复启停幂等，停止后不自行重连。
- 心跳、断线、过期、序列缺口、RawIngress 写入失败和队列溢出必须使相关输入及候选失效；恢复必须取得新的健康输入并预热。局部故障不任意清空健康范围，整体失去计算能力时明确故障。
- 订阅按所有者共享，局部配置修改增减对应订阅；停止或暂停先撤销候选，再释放本扫描订阅，不停止其他消费者。
- 配置版本化保存，服务重启恢复配置并默认停止。复用待整合实现已有的服务端滚动历史，明确保留窗口、重启清空及覆盖范围；不在本轮新增 SQLite 或跨重启长期历史承诺。
- 页面刷新不清空服务端已有历史；服务重启不得续接中断事件寿命。配置、操作和历史接口如实返回缺口与可查询覆盖。
- 核心白名单及回执流程保留真实权威边界；本轮不扩展交易审批能力，未接核心时显示不可用，不能生成接受回执。

### 实施顺序

| 阶段 | 交付 | 依赖 | 完成依据 |
|---|---|---|---|
| 1 | 扫描后端整合到现有控制面 | 无 | 正常登录与扫描 API 可配置、查询和启停；能力缺失如实返回 |
| 2 | OKX／Hyperliquid 环境与目录能力 | 1 | 受支持项可配置，不支持项拒绝；环境和身份贯通 |
| 3 | 两家正式内部行情输入链 | 2 | transport 协议夹具经实际适配器和投影到扫描，原始证据可追溯 |
| 4 | Web 操作、结果、证据和历史 | 3 | 正常 UI 全链路、缺证据展示及生命周期行为通过 |
| 5 | 故障、恢复与统一启动交付 | 4 | 故障向量、配置恢复、订阅隔离与启动说明通过内部集成验收 |

五阶段属于本规格实施顺序，不代表已完成或已另建任务；后续拆票仍沿现有本地 tracker 发布依赖。

## Testing Decisions

- 主验收接缝沿用用户已确认的完整链路：正常 Web 操作 → 现有控制面 → 扫描运行组装 → OKX／Hyperliquid 公共行情适配器与规范投影 → 扫描计算 → Web 结果、证据及历史。只在外部 transport 边界提供确定性协议输入，其他内部环节使用正式实现。
- 不再重复采访测试范围；本规格落实已批准的“项目内部整合接通、在线行情另验”计划。HTTP、IPC 和 UI 不得直接注入最终候选代替两家适配器。
- 正向验收以实际 HTTP 会话和 API 驱动，浏览器至少覆盖一次正常登录、配置、启动、结果、证据、历史和停止。可复用已有浏览器测试先例；仅 mock 扫描 HTTP 响应的页面测试不作为整合证据。
- 复用 MarketFeedAdapter 契约、两家 Venue 的公开解码／深度测试、扫描器公开测试和扫描控制台离线 Web 验收先例。已有单元测试只用于定位故障，不能替代上述完整链路。
- 正常向量覆盖至少一个受支持的跨 Venue 共同暴露资产配对，按实际产品和报价资产规则配置；同名不同资产、不同结算单位不得误配。每个声明支持的环境路由和两家协议路径都必须被内部测试覆盖。
- 故障向量覆盖无目录、规则缺失／不匹配、未知深度、缺费用／模型／校准、无机会、重复和乱序输入、旧会话、环境切换、TTL 到期、断连、重连预热、原始输入写入失败和容量溢出。
- 操作向量覆盖未登录／CSRF 错误、配置版本冲突、重复启停、暂停恢复、局部范围变更、共享订阅释放、页面刷新及服务重启。验证公开状态与结果，不断言内部线程或私有容器结构。
- 所有测试输入标记为合成协议夹具；内部测试不连接 Venue 网络，不读取 Demo／生产凭证，不发送交易请求。时间由可控制时钟推进，不靠真实长时间等待通过测试。
- 按实际改动运行受影响的 Python、Zig 及 UI 检查；涉及 Zig 行情与环境合同的回归覆盖仓库固定编译器的 Debug 和 ReleaseSafe。记录命令、版本、输入、结果和未执行项。
- 在线端点连通、真实盘口正确性、长期新鲜度、网络限流及持续运行测试归另一计划。本规格成功只声明内部整合通过，经济资格、运行资格和生产资格保持原状态。

## Out of Scope

- 本次发布规格时修改实现代码、执行部署或连接交易所。
- 实际交易所端点可达性、在线数据正确性、长时间行情新鲜度、真实网络限流与稳定性验收；不沿用前案的 30／60 分钟门槛。
- OKX／Hyperliquid 以外的 Venue、自动扩展到全部产品和全市场订阅。
- 真实或 Demo 下单、凭证录入、交易策略加载、白名单核心授权扩展及经济／运行／生产资格关闭。
- 新控制面、通用插件框架、新历史数据库及长期历史存储工程。
- GitHub Issues 同步。
