## Question

Linux I/O 放在哪里，队列或消费者落后时系统如何保持安全？

## Answer

- `io_uring` 用于网络和日志 I/O 接缝，不作为内部事件总线；是否启用 SQPOLL、零拷贝等能力必须通过目标硬件基准决定。
- I/O 线程与 TradingShard 之间优先使用有界 SPSC 通道。
- 交易核心不等待外围消费者，也不使用无限队列。
- L2 增量行情发生溢出时标记为 Gap、停止相关新开仓并重新同步快照；不能任意丢弃增量后继续交易。
- 可重新推导的 BBO、指标和监控值可以合并到最新状态。
- 订单、成交、账户、风控和控制事件不能静默丢弃；无法可靠处理时失败关闭并停止新订单。
- 分片决策日志超过安全积压阈值时停止开仓；原始行情日志可以记录明确的 capture gap。
- Python 策略持续落后时停止该策略并通过完整快照重新同步。
