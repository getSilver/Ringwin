# 确定单活热备高可用模型

Type: grilling
Status: resolved
Blocked by: 04, 06, 07
Parent: [设计生产级多策略低延迟加密量化交易系统](../map.md)

## Question

生产节点如何容灾，并在更新静态编译策略时避免双主或失去可恢复性？

## Answer

- 每个交易账户/决策域使用单活主实例和热备实例，不在同一账户上运行双活交易核心。
- 主实例必须持有有效租约与单调递增 fencing token；执行网关拒绝旧 token 的订单。
- 热备持续接收事件及订单日志并重放状态，但不持有交易权限。
- 故障切换前完成租约隔离、交易所对账和 Unknown 订单处理。
- 原生策略静态编译到 TradingShard，而不是整台节点的唯一巨型进程。
- 更新时旧版本热备继续承担故障恢复，新版本 Shadow 预热；切换后旧主升级为新版本热备。
- 首版先支持可验证的人工切换，自动切换取决于后续 RTO/RPO 决策。
