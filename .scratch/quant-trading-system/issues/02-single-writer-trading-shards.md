# 选择单写者交易核心与交易决策域分片

Type: grilling
Status: resolved
Blocked by: 01
Parent: [设计生产级多策略低延迟加密量化交易系统](../map.md)

## Question

交易核心采用何种并发模型，分片边界放在哪里？

## Answer

- 采用“单写者交易核心 + 异步并行外围”，不把 MPMC 流水线作为交易状态的默认模型。
- 每个 TradingShard 固定绑定一个物理核心，顺序处理行情视图、策略、本地风控和订单状态。
- 分片单位是交易决策域：共同完成同步决策的策略实例、虚拟投资组合、订单簿副本、多条交易腿和风险预算必须位于同一分片。
- 分片之间并行，但不共享可变对象；跨分片只传递不可变事件或快照。
- 同一行情可以扇出到多个分片，同一真实账户可以向多个分片分配独立风险额度。
- 网络、日志、监控、控制和重计算属于异步外围。
- Venue 行情 Adapter、规范化/健康检查、Execution Gateway 和全局风险额度分配属于共享外围，不为每个 TradingShard 复制；行情只向实际订阅它的分片扇出。
- TradingShard 内只保留必须共同确定排序的权威交易状态：本地 L2 视图、原生策略、VirtualPortfolio、本地同步风控、订单投影和 TimerEvent。
- TradingShard 只有一份实现。首个端到端纵向闭环先运行一个实例，验证正确性、重放和延迟后，再用同一实现扩到四个固定核心；这不改变首版单节点四分片容量目标。
- 四分片资格运行必须证明相对单分片没有因重复行情处理、跨线程排队或负载不均造成不可接受的 P99 退化，否则优化路由与分片归属，而不是复制共享模块。
