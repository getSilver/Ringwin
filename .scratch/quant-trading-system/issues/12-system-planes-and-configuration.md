# 确定三面架构与配置发布模型

Type: grilling
Status: resolved
Blocked by: 04, 06, 08, 09
Parent: [设计生产级多策略低延迟加密量化交易系统](../map.md)

## Question

完整系统的职责如何分面，代码和交易参数如何安全发布？

## Answer

- 交易面使用 Zig/C，负责行情、订单簿、交易分片、风控、OMS、执行和事件日志。
- 研究数据面使用 Python，负责历史数据、因子研究、分析、参数搜索和报告。
- 控制面负责策略版本、配置审批、部署、额度、健康检查和人工操作，不同步参与每笔交易。
- 三面共享版本化领域定义，但不共享运行时对象或数据库事务；交易面与其他两面失联后只在现有配置及额度有效期内安全运行。
- 原生策略代码通过 TradingShard 分片级蓝绿发布。
- 策略参数通过强类型、版本化 ConfigEvent 在明确 shard_seq 屏障生效，不使用任意字符串键值。
- 配置包含版本、内容哈希、生效条件、操作者和审批记录；回放加载相同配置事件。
- 收紧风险限制可立即生效，提高额度必须审批；回滚通过发布新版本完成。
