# 确定事件日志与快照模型

Type: grilling
Status: resolved
Blocked by: 03, 06, 07
Parent: [设计生产级多策略低延迟加密量化交易系统](../map.md)

## Question

哪些事件必须持久化，如何在不阻塞交易热路径的前提下支持审计、重放和恢复？

## Answer

- 原始接入日志由网关异步保存交易所原始行情、账户和订单回报，用于重新解析与审计。
- 每个 TradingShard 独立保存分片决策日志，记录标准化输入、配置变更、策略意图、风控结果、订单状态和成交。
- 分片决策日志是确定性重放的直接来源，不建立热路径全局日志写入器。
- 日志使用预分配分段文件、校验和和单调分片序号；日志线程通过 SPSC 接收事件。
- 在明确事件序号屏障生成周期状态快照；恢复使用快照加后续日志。
- 指标、临时计算及可重新推导的数据不进入权威日志。
- Kafka/Redpanda 等只能异步消费副本，不进入交易热路径。
