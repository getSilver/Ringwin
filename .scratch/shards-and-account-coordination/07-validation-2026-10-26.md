## 恢复选择规则

协调器快照加连续稳定协调日志尾决定协调 barrier；每片自己的快照加连续稳定日志尾决定真实 ShardSequence。四个 shard 序号不建立跨片总序，不能用最大序号或墙钟拼接恢复。

`AccountRecovery.beginWithCoordinatorTailInto` 先重放协调输入，再恢复四片，并从恢复后的真实状态导出摘要。每片摘要必须与协调器保存的完整摘要一致，包括发布版本、真实屏障、身份、规则、lease、订单和经济占用。唯一允许暂待刷新的是能由已验证 forced 分配及 shard 稳定提交完整解释的变化；额外经济输入不能混入，协调 ACK 必须有实际 shard 提交。缺段、损坏、错配及没有提交的 ACK 均失败关闭。

恢复对象在发布前必须全部验证成功。协调器和四片保留 RecoveryOnly；历史输入不能充当本次恢复的新账户或 margin 证据。完成协调器恢复前先检查四片模式和残留授权，任何错误均不能先解除协调器 fence。协调器准入成功也不替代四片各自的对账和人工授权。

## 实现

Core/Owner、OMS 和恢复协调器的临时状态存储及调用边界属于运行时代码改动；当前执行证据覆盖离线和 Windows/Demo 调用链，不代表 Linux 生产资格。`src/testing/` 及模块内 `test` 块的归属、恢复顺序和临时存储改动属于夹具修复；不能把夹具此前栈溢出当成生产进程同处溢出的证明，也不能将这部分计作生产性能提升。

- 保留单写者和稳定提交顺序。订单组的嵌套回滚保存其实际可变状态：OMS、Trace、operational state、cycles 和各账户八个 margin 字段；拒绝路径恢复这些字段，保留原有 margin 拒绝和未处理错误行为。次账户前态从当前账户视图读取，不再复制整片只为访问前态；回滚仍恢复正确账户视图。
- `Owner` 预留一份不可持久化的 `transaction_scratch`，复用于提交和提交前归档视图；归档 builder 独立持有数据，调用 `self.apply` 后不再读取旧视图。热路径不逐事件分配。代价为每个 Owner 多一份 TradingShard 的常驻内存，约 31 MB；四片约 126 MB。
- 所有实际 Demo Owner 按值初始化、恢复调用迁移到现有 `Into` 接口；Windows/Demo 启动和回归调用一并覆盖。纯快照 pin 构建和协调快照解码采用目标存储接口，避免 Debug 为大型错误返回值生成多份临时区。OMS 已有完整事务副本改用直接字节复制，保留验证和发布顺序。应用栈维持 64 MiB。
- 多账户 Owner 的 snapshot/tail 恢复通过 `restoreSegmentsWithScratchInto` 复用同一 runtime scratch，避免重放事务副本与账户摘要视图副本在栈上叠加。逐事实验证、截断尾和失败发布规则保留；没有新增逐事件分配。
- 独立的 `restoreSegmentsInto` 包装保持 `noinline`，使其局部恢复 scratch 在返回时结束，避免与随后 forced-tail 摘要解释的完整视图叠加。该 64 MiB 失败场景已定向 3/3 通过；双项复审确认无语义变化。
- 冷 fee 历史夹具通过只读借用经济投影及账户分区读取对账前后状态，并将 Gateway 检查的完整账户视图放在测试分配器上复用，避免按值账户返回临时区与完整视图在初始化链叠加。所有经济、恢复、重复、冲突、历史不可用及兄弟账户隔离断言保留；最终 64 MiB 定向 3/3 通过。
- 四片 fixture 使用正常 Host intent 路径建立风险证据。健康 Genesis replay、snapshot 恢复及 margin 对账中再次崩溃恢复等价；成功后四片仍处于恢复模式，历史 command/cancel 不重发。原有未分配 forced 轨迹保持失败关闭，并继续验证非空协调及 shard 日志尾的三路径等价。
- 新增实际四 Owner 原生恢复场景：独立组合反向持仓、实际 v2 RiskLease 投递、Owner/Coordinator 持久恢复、历史 bootstrap 不能替代新证据、新 bootstrap 后仍须新 margin、再次崩溃重新要求新证据。毛额 8、原生保证金 4、净额收益 4；每片 lease 25，总量 100，净额收益不形成额外租约。
- dual-IOC 夹具的首次订单和修复订单均填写既定 portfolio 10；恢复其真实风险拒绝路径。资产精度回归使用已有目标存储恢复接口。
- 完整套件暴露前票安全语义后的旧夹具：Host fault 和 lease fault 恢复都须显式打开原因、resolve latch、重新 enable，不能期待自动授权。按 ADR0021 补齐真实恢复输入；租约重放只比较有效 gate/latch 切片，避免读取未使用的 undefined 容量。单片五条轨迹更新旧格式冻结值；隔离基线源码复现相同三个失败，且五条 barrier/digest 与本次源码逐项相同，未放宽安全规则。
- 完整套件中的两处会计夹具同样在隔离基线复现失败：SPOT 订单成员补齐 portfolio 归属；模拟器身份冲突测试保留首笔真实 Fill 的业务身份，只改费用并使用新的接收 envelope，避免误造第二笔新身份超量成交。历史归档双 key 测试显式填写资格的账户 2；这些修复均不改变经济或身份校验。
- 控制与 forced 历史压力夹具按既有校验调整恢复顺序：打开同一原因 gate 后仍断言无交易权限，再用当前 version 构造 resolve，最后显式 resume 或 stop/归档；保留全部历史、账本和恢复断言。
- 连续/Windows 容量、residual 和 post-only 撤单的共享 intent 构造补齐组合归属，历史重试使用相同 fingerprint；Gateway 激活夹具显式填写组合 1。原生能力的无效配置输入采用零版本，不再把合法非零能力配置误判为无效。共享账户恢复分别核对挂单预留和包含持仓保证金的毛额摘要，保留上限与 lease 用量断言。
