# 02 让轮转 worker 安全复用同源全市场元数据

Type: task

Parent: [模块地图](../map.md)

## Question

怎样让轮转 worker 少发元数据请求，并继续基于当前 Instrument 规则安全采集盘口？

## What to build

让同一实际行情来源、同一响应适用范围内的 worker 短时复用全市场原始元数据。每个 worker 继续走原生 Instrument 身份与规则版本校验，校验通过后进入现有采集流程。

## 验收条件

- [x] 同源多个品种跨批次轮转时可复用仍有效的全市场响应。单品种响应按品种隔离。验证实际行情来源或响应适用范围不同时不会串用。
- [x] 保留原文和实际获取时刻，命中缓存不延长有效期。记录复用窗口及依据，验证到期后的并发请求仍合并为一个在途刷新。
- [x] 目录或规则变更、目录失效及需重新预热的断线恢复走明确刷新路径。验证变化前的迟到响应不会回填已失效条目，原生 worker 能识别变化后的规则。
- [x] 注入刷新失败和 429，验证受影响路线按既有规则降级或撤回，相关请求遵守现有退避，其他来源继续推进。恢复需通过新一轮校验与盘口采样。

## 实现与验证

- [运行说明](../../../docs/scanner-runtime.md#数据与生命周期)记录 5 秒复用窗口及依据。以响应返回时的单调时钟为起点，复用原文。原生 worker 重验仍以 30 秒为周期，截止时刻基于原始获取时间。
- [定向集成测试](../../../python/test_scanner_integration.py)经正式扫描调度启动原生 worker，覆盖 ETH／SOL 跨批次复用、到期后同批两个 worker 合并请求、Hyperliquid 主网与 Testnet 隔离以及 OKX 单品种隔离。
- 在请求尚未返回时更改目录中的规则，验证旧响应未进入盘口采样，重开的 worker 使用新元数据通过原生规则校验。目录失败和断线后在 5 秒内恢复的 worker 也会重新请求元数据。
- 在公共 HTTP opener 注入 503 与 429，验证 Hyperliquid 腿降级、退避期不发新 HTTP 请求、不采样受影响盘口，OKX 腿继续推进。退避结束后要求元数据和盘口均重新采样才能恢复健康。
- 复用 [01](01-warmup-baseline.md#测量口径) 的 ReleaseFast 原生 worker 运行上述 7 个变更测试，全部通过。三档容量与新鲜覆盖率对照由 [03](03-verify-capacity-and-freshness.md) 复测。
