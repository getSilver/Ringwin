# 设置驱动扫描实施地图

Status: open

来源：[18：交易所设置驱动扫描范围与动态市场发现规格](../cross-venue-arbitrage/issues/18-settings-driven-scanner-spec.md)。原规格保持原状，本地图维护六张实施票的依赖与进度。

## Destination

用户保存交易所设置后，在扫描范围直接按配置名称选择交易所，公共接口动态提供品种与规则，现有 Python 请求／调度 → Zig MarketFeedAdapter／规范投影／RawIngress → Python 扫描计算链路按范围运行。

## Definition of done

- 六张票均有可复查的公开行为验证及实现证据，来源规格的验收条件全部被覆盖。
- 设置与范围独立持久化，名称必填，重启默认停止；不依赖手工市场登记文件。
- OKX 与 Hyperliquid 动态发现均经过实际 Python／Zig／页面链路，至少覆盖两个原名单外品种的有依据跨所配对；不得扩大或迁移静态名单。
- 正常运行按动态配对和最新规范盘口供应合法数量及三种执行计划，复用既有完整周期经济／预测／概率评估；完整成本后能明确通过或拒绝，数据不足／预热由实际输入决定。
- 费用、模型、校准、参数、资金／风险约束和资产关联均有版本、适用域和有效期；失效立即撤销旧机会，扫描与直接评估一致，历史可复算。
- 刷新、规则变化、退市、环境切换、改名、删除和错误恢复保持身份、单位及订阅隔离正确。
- 完整浏览器／控制面／适配器内部验收通过，明确协议夹具证据与在线行情资格的区别。

## Rules

- 2026-11-15 发布阶段：用户确认六张纵向功能票及阻塞关系，授权发布本地票；当次未认领实现、不部署、不连接交易所、不同步 GitHub。后续实施按各轮明确授权进行。
- 每票 Type 为 task、Status 为 open、Triage 为 ready-for-agent；Triage 不取消 Blocked by。每次只认领一张无未完成 blocker 的 Frontier 票。
- 遵循根级 GLOSSARY 和 ADR 0001／0012：公共行情独立于 ExchangeAccount，扫描观察不改变核心资产定义或交易授权。
- 复用现有控制面、配置存储方式、扫描公开接口和 MarketFeedAdapter，不建立新能力声明流程、数据库或插件框架。
- 每票包含从用户操作到可见结果的验证；只在公共网络 transport 提供确定性协议输入，保留实际 Zig 解码和规范投影。
- 01 建立最小共享设置／目录合同供 02、03、05 使用；02 与 03 不互相阻塞，不要求额外基础设施票。05 的生命周期行为先基于已有来源验证，动态来源组合由 06 补验。
- 01–05 可保留现有入口作为内部实施过渡，不能要求用户为新增动态来源维护静态品种表；06 删除旧入口和最终依赖。每张票仍须独立通过受影响检查。
- 完成后填写本票 Answer 与证据，再更新本地图 Frontier；不得因拆票发布或局部通过关闭来源规格。
