## Question

如何让动态市场变化正确影响扫描范围与候选，同时保留新品种策略、容量控制和订阅隔离？

## What to build

从用户选择的动态市场范围持续刷新两家交易所目录；页面显示实际覆盖和故障，规则变化、暂停、退市或恢复只影响相关来源。新增品种按照已保存纳入策略参与扫描，正常来源保持运行。

## Acceptance criteria

- [x] 首次发现和运行中定期刷新均走真实协议解码，刷新周期有明确实现记录；加载／失败状态不删除设置中的交易所选项。
- [x] 支持完整处理声明发现范围内的分页与有界大响应；超消息或驻留容量明确报告覆盖／失败，不将截断目录标为完整，不保留失效旧候选。
- [x] 新发现品种仅在新品种纳入开关允许且满足资产纳入／排除、产品和深度规则时新增订阅；关闭开关保留原登记范围，不自动订阅全市场。
- [x] 规则变化、暂停、退市或品种消失及时撤销相关有效输入和候选；恢复后采用新规则版本重新预热，不混用旧盘口。
- [x] 元数据请求失败、网络断连、TTL 到期及恢复有可见状态；受影响来源之外的订阅和其他消费者所有权保持独立。
- [x] 公共发现不改变核心 AssetDefinition 或 InstrumentRules 权威配置，单位不明确的品种明确拒绝参与有效机会计算。
- [x] 两家实际适配器的确定性更新序列通过前端／控制面到扫描结果验证，覆盖新增、规则改变、退市、恢复、分页、容量及局部范围变更。

### 实现

- 已保存且已应用范围的动态来源每 30 秒后台刷新完整目录，失败同周期重试；目录 TTL 90 秒，使用进程内单调时间。发现仍经过实际 Zig 协议解码与 DurableStore RawIngress；后台网络请求不占用盘口 poll 锁。设置选项始终保留，页面显示 loading／failed、具体错误及拒绝原因；成功状态另有 count／complete／周期合同。
- 以 Venue／环境替换该来源的动态目录，撤销消失、暂停、退市、坏规则或单位不明确的输入；规则内容变化关闭旧 worker／session 并清除旧盘口，恢复后使用新规则及新订阅重新预热。配置保存时的登记身份保留，新增仅在 new_instruments 允许且匹配产品和资产纳入／排除时订阅；深度仍在实际新盘口发布时按报价单位判断。
- 元数据失败、超限或 TTL 过期立即清除相关有效输入和已有候选，原子缓存不写部分解码结果。目录／活跃订阅容量超限显示失败，不把部分覆盖当作完整；订阅上限仍为 16。来源外的 worker、输入及其他消费者所有权独立；停止只释放扫描器自己的订阅。
- 复用现有目录、设置、缓存、MarketFeedAdapter 和控制面，不改变核心 AssetDefinition、InstrumentRules、账户或交易权限。旧显式配置只保留到 06 的过渡边界；目录刷新不新增静态维护要求。
- 当前声明接口是 OKX `/api/v5/public/instruments` 的完整 SPOT／SWAP 响应，以及 Hyperliquid `/info {type:meta}` 的标准永续完整 universe。两者目录没有分页游标，故分页条件在当前范围不适用；不模拟不存在的游标，也不声称覆盖历史查询或 HIP-3。官方合同链接及容量见 `docs/scanner-runtime.md`。完整大响应、4097 行失败及驻留／订阅容量有回归，无截断成功路径。
- 主代理复核补上 TTL 锁内重新检查，避免等待锁时刚提交的目录被误判过期；恢复缓存中的动态绑定会补建来源状态，即使上次持久化时该来源不在 ready 状态，重启后仍可按保存范围重新发现，默认停止且不产生订阅。
