## Question

如何证明正常入口从空设置开始即可完成设置、发现、范围选择和扫描，且不再依赖旧静态市场配置？

## What to build

完成最终运行组装并移除旧手工市场登记的读取、启动条件和过渡调用，更新当前启动说明、夹具和验收入口。通过浏览器操作完整验证两家交易所动态发现、扫描及设置生命周期，保留现有 Python／Zig 协作和行情证据链。

## Acceptance criteria

- [x] 没有旧静态市场配置时正常应用仍提供设置和扫描入口；空设置不伪造交易所或行情，也不因缺少该文件拒绝组装扫描器。
- [ ] 从空运行目录，经前端登录、保存两家交易所、加载公共目录、选择范围并启动，实际 Python／Zig／页面链路发现名单外资产并进入正式评估；缺项如实展示，完整输入给出真实通过／拒绝结果。历史目录／盘口接通不满足此条件。
- [x] 动态来源不再读取旧手工品种表；删除固定两家组合／三品种业务白名单及旧启动依赖，更新当前脚本、夹具和文档，历史验收记录原身份保留。
- [ ] 至少两个原名单外品种及 Hyperliquid 品种经过实际解码、规范投影、可靠关联与正式评估；动态来源组合覆盖 04 的目录生命周期和 05 的改名／删除／环境切换行为。
- [x] 刷新页面、服务重启恢复交易所设置及范围，默认停止且不自动请求行情；用户后续操作可重新发现并运行，身份和单位稳定。
- [ ] 完整浏览器验收确认所有名称与设置一致、范围过滤生效、错误与恢复可见；认证／CSRF、配置失败恢复、TTL、迟到结果、局部订阅隔离和适配器契约回归通过。
- [x] Python 公共请求和调度、Zig native worker／MarketFeedAdapter／RawIngress／规范投影、Python 扫描计算保持完整；原始行情审计仍可用，无凭证读取、交易授权或下单副作用。
- [x] 发布可复查内部验收记录和启动说明，列明合成协议输入、实际执行检查及未取得的在线行情证据；不把内部通过视为在线、经济、运行或生产资格。
- [x] 汇总六票对来源规格验收条件的覆盖及剩余项，完成后更新本地图；来源规格不因票发布或局部通过自动关闭。

## Answer

### 2026-11-17 复用已有资产登记与配对器

用户后续确认本轮先移除 BTC／ETH 硬编码，并复用已有资产、单位和产品规则接入配对。已删除特殊名单，新增核心已生效 AssetRegistry 的只读代码绑定投影，并在正常 Web 运行组装供应给 scanner；适配器校验的动态目录按 Venue／Environment／代码查找既有登记，继续调用原扫描配对器。没有按同名、大小写或去前缀合并，没有新增用户可信品种文件。

已登记 SOL／DOGE 经实际 Python／Zig／HTTP 形成候选；同名不同资产、未登记 BTC、未登记 kSOL／包装名称不误配，显式等单位别名、目录／登记换序、重启和环境隔离保持正确。登记变更撤销旧候选并重绑原筛选，原 registered 集合、新品种开关和部分写入恢复回归通过。最终受影响 Python 83/83、Zig 定向 2/2、projection probe 构建及语法／格式／差异检查通过。

边界：只有已有生效登记的品种获得关联。独立公共入口未供应 ProjectionProvider 或缺少具体登记时保持来源隔离，缺项按品种记录；没有解决所有未登记动态资产的身份依据，也没有实现跨 segment／snapshot 登记恢复。正式评估输入仍为空，形成候选不等于评估通过。没有在线／浏览器验收，不关闭下方完整验收条件，06 保持 open。详见[实现、证据和限制](../../../docs/research/2026-11-17-scanner-registered-asset-pairing.md)。未提交、推送或部署。

### 2026-11-16 两层业务缺口：前置核验，尚未修复

按用户本轮请求，最终行为必须为动态目录 → 有身份及单位依据的跨所配对 → 正式完整周期评估 → 页面通过／拒绝／数据不足结果。BTC／ETH 固定关联与永久 missing_evidence 均不满足验收，原先目录与盘口通过记录不能关闭本票。

- [ ] 删除 `STANDARD_PERP_UNDERLYINGS`，不转移成其他静态名单；先解决 Hyperliquid 官方资产身份来源，按适配器验证目录建立可追溯、带版本关联；包装、别名、缩放、同名不同资产及环境保持精确隔离。
- [ ] 关联变化协调范围、缓存、订阅与历史；关闭新品种时保留原登记集合，重启／换序身份稳定，部分写入恢复回归通过。
- [ ] 正常运行组装供应真实版本化费用、策略参数、模型、校准和资金／风险约束；核实研究实际产物，禁止导入测试夹具或制造合格校准。
- [ ] 依据最新规范盘口、乘数、步长、最小数量／名义和真实深度产生双 Taker／A Maker／B Maker 的合法 Plan，复用既有经济／预测／概率完整周期评估。
- [ ] 正确处理计价与实际结算资产，不按固定 1:1 合并 USDT／USDC；包含开平仓费用、资金费、部分成交及失败处置。
- [ ] 区分评估通过、评估拒绝、数据不足／预热，展示数量、净收益、风险、原因、输入版本和有效期，删除恒定缺项列表；输入失效立即撤销旧机会。
- [ ] 至少两个名单外品种实际 Python／Zig／页面通过；完整成本后拒绝和满足条件通过均有证据；扫描、直接评估和历史重算一致。内部确定性与在线验证分别记录。

本轮仅完成前置来源／源码核验与实际 native 红灯复现：SOL／DOGE 各两路规范盘口、各 worker 3 次 capture／6 条 RawIngress 记录，但候选 0；ETH 正常入口发布 plans=0，真实 evaluate 调用=0，3 个 missing_evidence 候选。三项所需验收全部失败，未写业务修复。在线公共目录获取成功，不等于在线盘口或经济验收。来源局限、研究供应缺口、经济单位边界及可复跑命令见[两层业务缺口核验](../../../docs/research/2026-11-16-scanner-business-gap-verification.md)。06 保持 open，未提交、推送或部署。
