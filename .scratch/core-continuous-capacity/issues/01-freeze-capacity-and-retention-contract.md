# 01: 冻结业务负载、容量和保留合同

Type: task
Status: resolved
Assignee: Codex
Blocked by: None (can start immediately)
Parent: [核心持续运行容量闭合](../map.md)

## Question

如何将三类策略、多交易对观察和部分做市转成可测的容量合同，区分同时存活订单、终态积压、历史事实与磁盘保留量？

## What to build

将三类策略、多交易对观察和部分做市转成可测的容量合同，区分同时存活订单、终态积压、历史事实与磁盘保留量。

## Acceptance criteria

- [x] 冻结约 500 个观察组合的口径为 Venue × 产品 × 交易对；容量覆盖 4 家交易所的路由/账户组合，三个策略类别为做市、资金费率套利和跨交易所套利。不假定全部组合参与做市，不实现策略或新增第四家协议。
- [x] 每分片 1,024 个同时存活订单，四分片各自达标；Unknown、PendingCancel 和其他未闭合风险订单计入，待归档终态单单独预算。做市活跃组合数和每边档数为负载参数，未确认的建议值不写成用户要求。
- [x] 盘点核心、OMS、经济投影、Gateway、控制事实、账户协调、canonical ingress、Adapter 和存储的所有累计容量，逐项声明耗尽行为、回收资格、历史证据与恢复语义。
- [x] 冻结可复现的持续/突发速率、冷热分布、归档滞后、撤单/回报/对账余量、内存/磁盘预算、保留与删除条件及恢复时限；缺少业务实测时标注合成负载假设，不虚构生产吞吐。
- [x] 明确全局屏障、历史身份查证和摘要连续承接方案，显式提出 ADR 0009 修订及 schema 演进；不以 SemanticAuthorityDigest 替代恢复完整性。历史 I/O 在核心之外，查证结果作为可验证、可重放输入。
- [x] 列出布局/计数/快照预算及复制成本验证方案；按 Windows/Linux 分别定义文件验收与证据格式。合同文档与容量矩阵可独立审查，实施状态仍未完成。
