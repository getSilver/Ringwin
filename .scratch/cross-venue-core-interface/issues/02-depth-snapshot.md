## Question

如何让策略只使用声明覆盖范围内、可证明且可重放的双边深度评估数量与成本？

## What to build

贯通 MarketFeedAdapter → CanonicalEvent → 行情投影 → StrategyInputBatch 的有界双边快照，保持捕获、可见盘口和重放一致。

## 完成条件

- [x] 档位绑定 Instrument、规则版本、源序列与可见时间，显式声明深度覆盖范围及截断。
- [x] 买卖对称覆盖至少多档深度、合法 tick/lots 与费用后净量；区分数量缺失和零数量。
- [x] 数量超出可证深度或价格保护边界时返回不足，不外推成交；覆盖 I1 的快照部分与 V2。
- [x] 经公共适配输入及 Host 输入验证正常、非法档位、容量溢出和不完整快照；不能生成虚假全量盘口。
- [x] 同一捕获输入重放得到相同可见盘口；迟到快照不改写历史决定。
- [x] 记录事件、编码、schema 的兼容策略及已有消费者处理方式；不得静默把旧单档输入视作完整多档深度。
- [x] 明确 L2 不提供 maker 排队位置、主动成交或条件执行资格。

## Answer

2026-10-21 完成离线实现与公共接缝验收。合同见 [双边深度快照合同](../../../docs/depth-snapshot-contract.md)，实际命令、结果与限制见 [02 验证记录](../02-verification.md)。

- `L2BookSnapshot.depth` 每侧最多 8 档，显式保留覆盖、截断和接收可见时间；OKX 负责精确 tick/lots 转换并校验被截断尾部。旧单档输入的 depth 保持缺失。
- 健康投影经独立 Host type 7 / schema 1 的 704-byte 负载贯通，Zig 与 Python 均校验；买卖报价按保护价格逐档累计，基础币与报价币费用采用保守舍入。附录 V2 从公共原始快照贯通 Host，支出 302，保护价 100 时返回不足；对称卖出收入 295。
- 原始捕获重放、规范编码重放、稳定日志及快照加尾恢复保持可见深度一致。拒绝不完整或可见时间不符的快照先持久保留 gap，防止旧健康深度继续暴露；第三档未知数量恢复后仍为 null。
- Canonical schema 14、codec 12、journal 40、state 44、registry 38，旧版本精确匹配失败关闭；兼容及旧消费者处理见合同。
- 完整隔离回归执行 652 项，首轮 650 通过、2 项旧断言失配；修正后受影响 5/5 定向复验通过，Python 5/5，格式和 diff 检查通过。未再次运行完整 652 项，不记作一次全量 652/652 通过。
- Standards 审查无违规；Spec 审查发现的旧盘口未失效问题已修复并复审通过。

本票只完成 I1 快照接缝与 V2，不关闭来源 spec 或宣称 I1 全链路资格。增量/重同步归 03；Python 策略状态 checkpoint 恢复归 08/09。Binance/Bybit 多档、跨 Venue 执行、maker 排队位置、主动成交、条件执行及任何线上资格未由本票授予。
