# 账户安全原因跨故障与恢复保留身份

四分片故障隔离沿用各自的单写者。账户 margin、凭证和 Gateway 限制以绑定 ExchangeAccount 与原因的稳定 SafetyGate 身份向相关分片投递；其他账户恢复不能覆盖它。原因 gate 与对应 latch 保持当前权限证据，不作为已完成观察归档。采用按故障代次更换 gate 身份，会使错过中间恢复投递的分片留下永远无法解除的旧 closed gate，因此不采用。

账户原因解除只打开该原因 gate；局部锁存和 TradingAuthorization 保留，各分片必须独立解决原因、人工 resolve 和 resume。重复故障重新锁存。Host fault 撤权和 lease 失效均锁存新增风险并生成规定范围撤单，故障前已取得资格的开仓命令也须重新校验。安全事实明确记录单调时钟，不能生成没有发送期限证据的撤单许可。

forced ingress 只有在原文、归属贡献、分配、经济应用与 ACK 的热或认证冷历史完整，四片已消费后续完整账户快照，且新 margin 证据健康时，才允许显式解除。协议冲突、未知原文或历史不可查证保持关闭。

这些输入的权威重放含义发生变化，Core journal/state/registry 从 49/53/47 升为 50/54/48；Coordinator 快照升为 18，旧格式失败关闭，不增加迁移或双读。离线验收不授予 Venue、生产栈或生产资格；最终四分片冻结摘要与完整资格仍由票 07 收口。
