# 使用分片全局屏障与有序历史承接

持续运行不能让内存 Trace 下标决定永久的风险、权限、策略游标或恢复身份。
本决策显式演进 ADR 0009 的驻留表示合同，同时保留其有序审计完整性要求及
SemanticAuthorityDigest 仅用于排列比较的限制。

## Decision

- ShardSequence 在同一分片内连续递增；权威屏障、事实引用、Host activation、
  风险决策和快照使用该全局身份。Trace 的驻留长度只用于窗口寻址及容量检查。
  溢出失败关闭，事务失败不提交新的屏障，不重置序号以获取容量。
- 票 02 先迁移所有消费者，仍保留从起点开始的完整驻留 Trace，并校验
  序号连续性、末尾屏障与驻留范围的等价关系；窗口满仍拒绝追加。
  这一步使用新的 journal/state/schema registry 身份 31/35/29，拒绝旧格式。
  CanonicalStateDigest 继续绑定完整有序 Trace、全局屏障、当前权威状态和
  canonical ingress 身份与顺序，不因新增独立屏障而移除审计证据。
- 票 03 才能在新的格式身份下引入检查点、轮转和历史承接。回收前须持久提交
  覆盖完整旧窗口的有序 SHA-256 链头、连续区间、规范输入内容摘要、归档根、
  历史身份索引根与引用范围；恢复验证前后链和当前状态、尾部及保留边界。
  CanonicalStateDigest 以域分离的有序历史承接替代已迁出内存的完整 Trace，
  不能仅用最终 OMS、经济投影或集合型 SemanticAuthorityDigest 替代。
- 历史 I/O 仍在 Owner、VenueAdapter 和 DurableStore 的外围。核心只消费
  绑定请求、命名空间、覆盖、屏障和已提交根的可验证、可持久化查证输入；
  cache miss 或证据不可用不能证明首次，冲突或过期未覆盖身份失败关闭。
  Unknown 和唯一已应用 canonical-fill 累计不会因迁出缓存被清除或重发。
- 删除只在保留合同及引用保护全部通过后执行，保留推进本身可重放。
  已提交的历史承接保护被合法删除记录的顺序承诺，不承诺仍能读取其载荷；
  仍在恢复或保留范围内的缺段、混合根或损坏不能猜测修复。

## Consequences

上述两个阶段分别改变表示和持久化恢复格式，每阶段独立验证并升级身份。
票 02 的通过不能证明已实现轮转、历史查证或容量闭合；票 03 必须通过公共
apply/snapshot/restore/Store 接口的多轮及故障验收后才能回收窗口。
新旧 schema 不建立长期双读双写或猜测迁移，既有平台和 Venue 资格不继承。
