# 以已提交对账窗口承接经济历史

票07延续ADR0013/0014的Store发布、Core持久提交、Gateway连续根承接顺序。初始economic baseline永久保留；重复从该baseline核对所有历史事实会耗尽有界证据，清空seen或减小累计计数则会漏掉事实。

## Decision

- FundingArchiveQualification保存原始Core或canonical语义、原时钟、账户/产品/资产/规则、原归属声明、实际经济摘要及全部相关LedgerTransaction。source摘要与已应用经济摘要分别认证；零金额没有账本事务仍保留结算身份。缺可信经济时间、未解决Suspense/ReconciliationBreak或缺历史归属证明的记录保持pin。canonical资金费不根据当前持仓补写归属。
- ReconciliationWindow保存完整原始规范输入、逐资产before/after余额、查询/来源证据、确切经济事实集合以及前cursor。只有全部热/冷事实认证、完整区间核对、当前余额一致且无未解决差异时可以发布窗口。
- 窗口发布并由Core持久提交后才推进ReconciliationCursor。新窗口from等于前through，before逐资产等于前after；窗口累计覆盖数量承接历史高水位，事实明细回收不能降低覆盖要求。初始baseline不重写，当前余额、仓位、成本、保证金和PnL不因归档改变。
- 窗口保留核对时的经济摘要；归档资格另绑定提交前的当前经济投影。行情更新及已认证明细归档不改写原窗口，也不使一个已核对窗口永久卡住；提交时仍重新核对余额、完整事实集合、来源与当前屏障。
- 旧身份先验证热证据或认证冷历史；same没有经济副作用，conflict锁存。闭合through之前的新经济身份失败关闭；缺可信来源时间不得用接收时间推进窗口或绕过边界。
- 开放经济事实集合的身份、经济摘要、原始可信时间、accepted输入摘要及数量/时间汇总由同一输入组的一条携带完整32字节摘要的派生日志事实认证；闭窗清空也发布新承诺，检查点保留此事实，41字节派生日志记录和重放逐字验证完整SHA256。恢复先核对日志承诺，再核对热记录；明细已冷归档也不能把新开放事实替换为旧闭合身份。正常journal重放从原输入重新生成承诺，不以重新封装快照摘要证明内部集合真实。
- 资金费、对账窗口与订单/成交使用不同typed历史身份，最新业务根区分各类提交。经济世代推进不释放accepted/Unknown，不授权发送；相邻根和前根链必须匹配。快照、摘要及恢复交叉校验同步演进，旧格式失败关闭。

## Consequences

本票只验证小规模公共功能及故障恢复；未完成的强制执行分配/ack仍保持pin，由08继续处理。不授予Venue历史FundingAllocation、容量压力、Windows/Linux平台或生产资格。
